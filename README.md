# payload-lint

Lint rules that enforce [Payload CMS](https://payloadcms.com) best practices on Local API calls — so code written by hand or generated by AI agents is caught by the linter instead of manual review.

The same five rules ship for two linters:

| Linter | Package                                                          | Setup                                  |
| ------ | ---------------------------------------------------------------- | -------------------------------------- |
| Biome  | [`biome-plugin-payload`](packages/biome-plugin-payload#readme)   | GritQL files in `biome.json`           |
| Oxlint | [`oxlint-plugin-payload`](packages/oxlint-plugin-payload#readme) | `jsPlugins` entry in the oxlint config |

## Rules

| Rule                               | What it catches                                                                                                                                                                                                           | Severity |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `no-find-without-select`           | `payload.find` / `payload.findByID` / `payload.findGlobal` / `payload.findVersions` / `payload.findVersionByID` calls that do not pass a `select` object, causing more fields than needed to be fetched from the database | `error`  |
| `no-find-without-depth`            | The same read operations that do not set `depth` explicitly — omitting it uses the application default (1), silently populating one level of relationships                                                                | `error`  |
| `no-missing-override-access`       | Any Local API call that does not declare `overrideAccess` explicitly — the Local API bypasses access control by default (`overrideAccess: true`)                                                                          | `error`  |
| `prefer-explicit-populate`         | Read operations with `depth` > 0 (numeric literal) that do not pass a `populate` object, so populated related documents return more fields than intended                                                                  | `error`  |
| `require-user-with-override-false` | Any Local API call with `overrideAccess: false` that does not pass `user`, `req`, or `user: null` — without a user object, access control functions receive `undefined` and behave unpredictably                          | `error`  |

All rules match any receiver that is the identifier `payload` or a member expression ending in `.payload` (e.g. `req.payload`, `this.payload`).

`prefer-explicit-populate` is a heuristic: it only fires when `depth` is a positive numeric literal (`depth: 2`). Shorthand (`depth`) and computed values (`depth: opts?.depth ?? 0`) cannot be verified statically and are skipped. If the target collection defines [`defaultPopulate`](https://payloadcms.com/docs/queries/select#populate) in its config, Payload already limits which fields are returned during population — suppress the diagnostic in that case.

## Install

```sh
# Biome
bun add -d biome-plugin-payload

# Oxlint
bun add -d oxlint-plugin-payload
```

See the package READMEs for the exact configuration, suppression syntax, and limitations:
- [Biome setup](packages/biome-plugin-payload#enable)
- [Oxlint setup](packages/oxlint-plugin-payload#enable)

## Repository layout

```text
fixtures/                          Shared test fixtures used by both packages
packages/biome-plugin-payload/     GritQL rules published as biome-plugin-payload
packages/oxlint-plugin-payload/    JS plugin published as oxlint-plugin-payload
```

## Development

Requires [Bun](https://bun.sh).

```sh
bun install
bun run test     # runs both packages' Vitest suites
bun run check    # Biome check for the whole monorepo
bun run fix      # apply safe fixes and sort package.json files
```

Each package has its own test suite. Both suites run against the shared `fixtures/` directory and assert the same diagnostics and messages, so the Biome and Oxlint implementations do not drift silently.

## Releases

Each package is versioned and published independently. The root package is private and is never published.

```sh
bun run publish:biome
bun run publish:oxlint
```

Publishing runs the package's test suite through `prepublishOnly`. Tag releases with the package name and version, for example `biome-plugin-payload@0.1.5` and `oxlint-plugin-payload@0.1.0`.
